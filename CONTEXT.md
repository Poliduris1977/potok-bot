# ПОТОК

ИИ-агент для квалификации входящих заявок на кухни на заказ.
Принимает сообщения от покупателей в Telegram и Макс, выясняет потребности и записывает на замер.

## Язык

**Замер**:
Бесплатный выезд дизайнера к клиенту для снятия размеров. Главная конверсия всего диалога.
_Избегать_: визит, встреча, выезд специалиста.

**Горячий лид**:
Лид с заполненными 4+ полями чеклиста. Требует немедленного уведомления директора.
_Избегать_: тёплый клиент, заинтересованный пользователь.

**Чеклист**:
Набор из 7 полей (product, size, style, budget, deadline, address, contact), которые нужно выяснить у клиента. Прогресс хранится в `ChecklistProgress`.
_Избегать_: анкета, форма, опросник.

**Передача**:
Перевод диалога на живого специалиста компании. Триггер: явная просьба клиента, корпоративный запрос, 5+ сообщений без прогресса.
_Избегать_: эскалация, переключение, перевод на оператора.

**Запись**:
Подтверждённая договорённость о замере с адресом и временем. Лид переходит в статус `booked` только через FC `book_appointment` — не автоматически.
_Избегать_: бронирование, назначение встречи.

**Лид**:
Запись в БД о конкретном клиенте на конкретной платформе. Один клиент = один лид независимо от количества диалогов.
_Избегать_: пользователь, контакт, клиент (в контексте БД).

**Сессия**:
In-memory запись в SESSION_CACHE per user_id. Хранит активного провайдера и pii_map. Живёт 30 минут с момента последнего сообщения.
_Избегать_: кэш пользователя, контекст соединения.

**Деперсонализация**:
Замена персональных данных токенами ([ТЕЛЕФОН_0], [ИМЯ_0]) перед отправкой в DeepSeek. Применяется только для иностранного провайдера — требование 152-ФЗ.
_Избегать_: анонимизация, маскировка, шифрование.

**Токен**:
Плейсхолдер вида [ТЕЛЕФОН_0], заменяющий реальные ПД в запросах к DeepSeek. Не путать с OAuth-токеном GigaChat или токеном Telegram-бота.
_Избегать_: placeholder, маска.

**Провайдер**:
Активный AI-сервис для текущего диалога: `deepseek` или `gigachat`. Хранится в сессии. Новый диалог всегда начинается с DeepSeek.
_Избегать_: модель, движок, сервис (без уточнения).

**Fallback**:
Автоматическое переключение с DeepSeek на GigaChat при сбое основного провайдера. В рамках одного диалога провайдер не возвращается назад.
_Избегать_: резервный режим, запасной провайдер.

**FC (Function Calling)**:
Механизм вызова агентом инструментов: save_lead_data, book_appointment, transfer_to_human, get_product_info. Существует в четырёх форматах (A/B/C/D) под разных провайдеров.
_Избегать_: функция, инструмент, тул (без уточнения FC).

**fc_trail**:
Накопленный список FC-вызовов текущей агентной итерации. Не сбрасывается между итерациями — модель видит всю цепочку вызовов.
_Избегать_: история вызовов, лог функций.

**Контекст клиента**:
Сообщение `[КОНТЕКСТ КЛИЕНТА]` с актуальными данными лида, добавляемое в начало working_messages. Деперсонализируется перед DeepSeek. Отдельно от системного промпта — для сохранения prefix caching.
_Избегать_: профиль клиента, данные лида в промпте.

**Уведомление**:
Сообщение директору в Telegram и/или Макс при смене статуса лида. Отправляется параллельно в оба канала. Телефон в уведомлении маскируется.
_Избегать_: алерт, нотификация, оповещение.

## Статусы лида

- `new` → дефолтный статус при создании
- `hot` → filled_count >= 4, уведомить директора
- `booked` → агент вызвал `book_appointment` FC
- `transferred` → агент вызвал `transfer_to_human` FC

Статусы переходят только вперёд. `booked` не устанавливается автоматически при получении контакта.

## Платформы

- **Telegram** → `bot/telegram.py` → webhook `POST /webhook/telegram`
- **Макс** → `bot/max.py` → webhook `POST /webhook/max`, домен `platform-api.max.ru`

Бизнес-логика общая — `bot/dialog.py`. Адаптеры только нормализуют входящий формат в `IncomingMessage`.

## Отношения

- **Лид** имеет один или несколько **Диалогов**
- **Диалог** содержит много **Сообщений**
- **Сессия** привязана к `user_id` (не к диалогу) — живёт в памяти
- **Замер** создаётся из **Лида** только через **Запись** (`book_appointment`)
- **Уведомление** отправляется при каждой смене **Статуса лида**

## Пример диалога

> **Разработчик:** "Когда лид становится `booked`?"
> **Эксперт:** "Только когда агент вызвал **FC** `book_appointment` и клиент назвал адрес. Получение телефона само по себе не делает лид `booked` — это просто прогресс **чеклиста**."

> **Разработчик:** "Почему контекст клиента не в системном промпте?"
> **Эксперт:** "Системный промпт статичный — он кэшируется у DeepSeek. **Контекст клиента** меняется после каждого **FC** — если его вставить в промпт, кэш сбрасывается на каждой итерации."

## Зафиксированные неоднозначности

- **"токен"** использовалось для трёх разных вещей: OAuth-токен GigaChat, токен Telegram-бота, плейсхолдер деперсонализации. Разрешено: "токен" без уточнения = плейсхолдер деперсонализации; остальные — с явным контекстом.
- **"сессия"** путалась с "диалогом". Разрешено: сессия = SESSION_CACHE in-memory запись (TTL 30 мин); диалог = запись в БД с историей сообщений.
- **"передача"** иногда означала передачу специалисту, иногда — fallback на GigaChat. Разрешено: передача = всегда живому специалисту; переключение провайдера = fallback.
